# Rencana: Setup Monorepo Chalista Academy + PRD

## Fase 1 — PRD (`docs/PRD.md`, dibuat lebih dulu)

PRD dalam Bahasa Indonesia berisi: ringkasan produk (platform kursus online + kelas live via Zoom), persona, success metrics, **scope MVP per app**:

- **learn** (web siswa & publik): landing page, katalog & detail kursus, enroll, "My Learning", jadwal kelas live, tombol join live class, auth dasar
- **server** (API): auth (JWT), CRUD courses/modules/lessons, enrollment, live-sessions (simpan Zoom meeting number/passcode), endpoint signature Zoom untuk Meeting SDK
- **zoom-client** (sandbox testbed): form join meeting (meeting number, passcode, nama), embed via `@zoom/meetingsdk` dengan pilihan Client View / Component View, signature diambil dari `server`

Plus: user stories + acceptance criteria, arsitektur monorepo (diagram), tech stack, non-goals/out-of-scope (payment, mobile, notifikasi → Fase berikutnya), milestone, risiko (vinext eksperimental; Zoom SDK butuh SDK Key/Secret dari Zoom Marketplace), open questions.

- Node 22 / pnpm 10, TypeScript strict.

## Fase 3 — Packages (ringan dulu, isi mengikuti PRD)

1. **@chalista/config** — `tsconfig.base.json`, `tsconfig.react.json`, `tsconfig.server.json`.
2. **@chalista/types** — zod schemas + tipe domain: `User`, `Course`, `Module`, `Lesson`, `Enrollment`, `LiveSession`, `ZoomSignatureRequest/Response`.
3. **@chalista/api-client** — wrapper fetch bertipe (base URL configurable), endpoint map mengikuti API server.
4. **@chalista/ui** — `cn()` helper (clsx + tailwind-merge), beberapa komponen dasar (Button, Card, Input, Badge) yang dipakai learn & zoom-client.

## Fase 4 — apps/server (hono, target Cloudflare Workers)

- `hono` + `@hono/node-server` (fallback dev) & `wrangler` untuk dev/deploy Workers (`wrangler.jsonc`).
- Struktur: `src/index.ts` (entry Workers), `src/app.ts` (Hono app murni), `src/routes/{auth,courses,enrollments,live-sessions,zoom}.ts`, `src/middleware/`, validasi via `@hono/zod-validator` + `@chalista/types`.
- Endpoint: `POST /auth/login` (stub sederhana), CRUD `/courses`, `/enrollments`, `/live-sessions`, `POST /zoom/signature` (generate signature Meeting SDK via HMAC — dibaca dari env `ZOOM_SDK_KEY`/`ZOOM_SDK_SECRET`).
- Data MVP: in-memory store (interface repository) supaya bisa ditukar D1/DB nanti.

## Fase 5 — apps/learn (vinext + Tailwind v4 + shadcn)

- Deps: `vinext`, `vite`, `react`, `react-dom`, `tailwindcss` v4 + `@tailwindcss/vite`.
- `vite.config.ts` dengan plugin vinext; struktur App Router Next-style: `app/layout.tsx`, `app/page.tsx` (landing), `app/courses/`, `app/courses/[slug]/`, `app/login/`, `app/my-learning/`.
- **shadcn/ui**: setup `components.json` + CSS variables Tailwind v4 (`@theme inline`) + `lib/utils.ts`, lalu tambahkan komponen via `shadcn` CLI (button, card, input, badge, dsb.). Fallback jika CLI tidak mengenali vinext: pasang komponen dari registry secara manual (dokumentasikan di README app).
- Halaman awal menarik data dari `server` via `@chalista/api-client` (dengan fallback mock bila server mati, agar DX dev tetap enak).

## Fase 6 — apps/zoom-client (vite + react)

- Deps: `vite`, `react`, `@zoom/meetingsdk`.
- Halaman tunggal: form meeting number/passcode/nama → minta signature ke `POST /zoom/signature` di server → render `ZoomMtg` (Client View) atau Component View.
- Catatan env: `.env.example` berisi `VITE_API_URL`; README menjelaskan pembuatan SDK Key/Secret di Zoom Marketplace.

## Fase 7 — Wiring, Verifikasi & README

- Root scripts: `dev` (parallel semua app), `lint` / `lint:fix` (oxlint), `format` / `format:check` (oxfmt), `typecheck`, `build`.
- Verifikasi: `pnpm install` → lint & format bersih → `tsc --noEmit` semua paket → build tiap app → smoke test dev server (server di :8787, learn di :3000, zoom-client di :5173) lalu dimatikan lagi.
- `git init` (tanpa commit) + README root: cara jalanin, struktur, link ke PRD.

## Catatan Risiko

- **vinext** masih eksperimental — jika ada fitur Next.js yang belum didukung, fallback di dokumentasikan; struktur app/ tetap standar sehingga migrasi ke Next.js mudah.
- **shadcn CLI** mungkin tidak mendeteksi vinext → setup manual (sudah diantisipasi di Fase 5).
- Zoom SDK butuh akun Zoom + SDK credentials; tanpa itu, app tetap jalan sampai langkah join (dengan pesan error jelas).
